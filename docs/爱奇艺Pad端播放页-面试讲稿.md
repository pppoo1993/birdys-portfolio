# 爱奇艺 Pad 端播放页 · 面试讲稿（10 分钟内）

> 基于作品集「爱奇艺 Pad 端」项目内容整理，含主讲述版、高频追问应对与上场建议。

---

## 一、一句话定位（电梯陈述，约 20 秒）

> 这是爱奇艺 Pad 端播放页的一次架构重构。我们做手机端时把「密集布局」平移到大屏，结果「同构不同效」——手机端跑得稳，Pad 端却出现留存瓶颈。我的核心工作是：用数据加用研定位到「场景与心智错配」，确立「手机做互动、Pad 做降噪」的双端心智差异，并把播放页从「三分屏」重构为「二分屏」，最终推动 Pad 端完播率与连播率明显提升。

---

## 二、完整讲述版（约 8–9 分钟，主回答用）

### 1. 项目背景：一个「同构不同效」的数据反差

这个项目是爱奇艺 Pad 端播放页的**改版**，不是 0→1。接手时我们复盘数据，发现一个很扎眼的反差：**手机端和 Pad 端用的是同一套密集布局、同一套推荐策略，但手机端表现稳健，Pad 端却卡在留存瓶颈上。**

更关键的是，大屏原本该有的「连播优势」正在失效——用户在大屏上应该更容易一集接一集看下去，但数据没有兑现这个预期。这背后指向一个更严峻的问题：**Pad 端这批高净值用户，价值被系统性地低估了。**

我的第一个判断是：这大概率不是「功能缺失」，而是「场景与心智错配」——我们拿手机的逻辑在做大屏。

### 2. 诊断第一步：用研锁定「双端心智差异」

要验证这个假设，我没有直接画方案，而是先用数据锁定核心人群，再做深度访谈。

我们先通过后台数据圈定了 Pad 端的基盘用户——**19–31 岁、以电视剧追剧为核心场景的高活群体**。然后对这群「贡献了主要流量、却遭遇留存瓶颈」的人，做了 **30+ 场深度访谈和真实场景观察**，并追踪他们跨端的实际使用轨迹。

访谈结果非常清晰，我把高频诉求收敛成两个维度——**「沉浸体验」和「互动效率」**：

- **手机用户**反复说的是「快、互动、陪伴、热闹」，喜欢边看边刷评论发弹幕，热闹才有陪伴感；
- **Pad 用户**反复说的是「沉浸、专注、不被打断」，把 Pad 当「私人电影院」，弹幕和推荐反而是干扰。

由此我确立了这个项目最重要的一条准则：**手机做「互动」，Pad 做「降噪」——凡是和 Pad 的「沉浸体验」冲突的设计，都值得重新审视。**

### 3. 诊断第二步：用数据戳穿「三分屏」的结构性错配

有了「沉浸」这把标尺，我回头审视现有布局。原 Pad 端沿用手机端的**「三分屏」**：左上播放器、左下信息互动区、右侧内容推荐区。

光看结构还不够，我拉了站内使用频次数据，把功能按真实需求排了个序：

> **全屏观影 77.4% ＞ 切换选集 20.7% ＞ 内容推荐 6.8% ＞ 评论互动 0.92%**

这个数字一摆出来，两个问题就暴露了：

1. **高频功能被挤到狭小热区**——「切换选集」20.7% 的需求，却被压缩在一个局促的交互区，操作成本高；
2. **结构性错位**——需求最高的「全屏观影」只占了左上局部，而优先级最低的「内容推荐」却占满整个右侧。

这就是我说的「高需求、承载空间却偏少」的错配。同时我也补了一个硬件趋势的判断：Pad 屏幕宽高比正从 4:3 向 1.6:1 变宽（Gpad 占比已到 48%），物理空间的变宽，恰好给了横向架构重构的空间。

### 4. 策略：三条原则，给重构定调

诊断清楚后，我没有一上来就画架构，而是先收敛出三条设计策略，作为所有方案取舍的标尺：

- **内容优先**——播放器回归绝对主角，架构精简为「主内容 + 窄辅助」；
- **效率至上**——高频的「切换选集」要触手可及，低频的评论互动合理收纳；
- **商业克制**——把商业触达从「硬植入」变成「顺滑的场景服务」，在沉浸前提下自然融入。

这三条背后其实是同一个判断：**守护沉浸体验的底线，释放大屏的物理空间，实现商业与体验的温和共生。**

### 5. 方案：从「三分屏」到「二分屏」

接下来做架构推演，我对比了两个代表性方案：

- **方案 A（三分屏微调）**：拉宽观影区、把周边视频挪到右侧。结果局限很明显——选集和推荐之间的逻辑关联被打断、视觉动线乱，而且不同屏幕比例的适配成本高，维护困难。
- **方案 B（二分屏）**：确立「主内容 + 窄辅助」。左侧空间全部让位给画面，右侧做纵向切分——上方承载高频选集操作，下方收纳低频推荐。

最终选了方案 B。理由是它**同时满足两个条件**：既契合「沉浸优先」的用户心智，又契合 Gpad 1.6:1 宽屏的物理特性——沉浸和效率两头都占住了。

### 6. 落地与结果

落地后的形态是：左侧纯净观影区，右侧窄辅助列，信息各归其位。呼应「沉浸优先」，播控条做了**动态显隐**——无操作时自动收起、画面归零（纯净）；一触屏就即时唤起，操作触手可及。

结果：方案上线后，**Pad 端完播率与连播率均明显提升，人均观看时长同步上扬**，「沉浸优先」的重构价值得到正向印证。（*有具体数字就补：完播率提升 X%、连播率提升 X%*）

### 7. 一句话复盘

如果让我把这个项目浓缩成一句话，我会说：**它不是「把手机设计做大屏」，而是「按大屏的心智重新定义信息优先级」。** 改版的本质，是让「信息各归其位」——该沉浸的沉浸，该高效的触手可及。

## 三、高频追问与应对

**Q1：为什么不是微调三分屏，而是更激进的二分屏？**
> 因为微调解决不了根本矛盾。三分屏的病根在于「结构」——高需求的观影区被挤到角落、低需求的推荐区占了主空间，这是空间分配的问题，不是拉宽一点就能解决的。二分屏把「观影」和「辅助」彻底解耦，才能让高频功能和高需求区域各归其位。而且三分屏在 Gpad 这种越来越宽的屏幕上，适配成本会越来越高。所以微调是「打补丁」，二分屏才是「对架构」。

**Q2：你怎么证明「沉浸体验」是 Pad 端的核心心智，而不是你自己的假设？**
> 我没有拍脑袋。一是用数据圈定了核心人群（19–31 岁追剧高活），二是 30+ 场深访 + 跨端行为追踪，用户的原话高度一致——反复出现「私人电影院」「不想被打断」「专注」。这些证据交叉在一起，才敢把「沉浸」立为准则。后面功能频次数据（全屏 77.4% vs 评论 0.92%）又从行为侧印证了这一点：用户在大屏上就是要「看」，不是要「聊」。

**Q3：把「评论互动」和「内容推荐」藏起来，会不会损害商业化？**
> 这正是我要强调的一点——「藏」不等于「砍」，而是「克制」。策略里专门有一条「商业克制」，我们把低频的评论、推荐从「霸屏」变成「合理收纳」，把商业触达从「硬植入」转成「场景服务」。结果是完播率、连播率都涨了，商业转化没有被牺牲。原因很简单：用户待得住、看得久，商业空间才可持续；一上来就堆满推荐，反而把人赶走了。

**Q4：这个项目和「明星陪看直播间」都涉及爱奇艺，你怎么区分自己的角色和贡献？**
> 两个项目性质不同。直播间是「商业化增长」，我做的是体验和变现链路的设计；Pad 播放页是「架构重构」，我主导的是「数据诊断 → 心智洞察 → 架构决策」这条主线，尤其是「手机做互动、Pad 做降噪」这个双端心智的抽象，以及「三分屏 → 二分屏」的架构取舍。一个偏增长、一个偏重构，但底层都一样——用数据定位问题，用设计解决问题。

## 四、给你的上场建议

1. **开场就抛出「同构不同效」这个钩子**，让面试官立刻知道你这是一个「数据反差驱动的改版」，而不是「我把页面重画了一遍」。
2. **记住两个关键数字**：功能频次「77.4% / 20.7% / 6.8% / 0.92%」，以及心智金句「手机做互动、Pad 做降噪」。这两个是本项目最有力的证据，讲的时候要脱口而出。
3. **方案取舍一定要讲「为什么放弃方案 A」**。面试官最想听的是「你如何做决策」，而不是「你画了什么」。把三分屏微调的局限（动线打断、适配成本高）讲清楚，二分屏的胜出才立得住。
4. **把「改版」和「0→1」区分开**：这个项目的难度不在「想新功能」，而在「推翻已有结构」。主动强调「已有业务的架构重构比从零设计更难，因为要平衡存量用户习惯和结构升级」，会显得你对项目类型有认知。
5. **时间分配建议（10 分钟内）**：背景 + 心智差异（第 1–2 部分）约 3 分钟，架构诊断 + 策略（第 3–4 部分）约 2.5 分钟，方案 + 结果（第 5–6 部分）约 2.5 分钟。如果时间紧，优先保「心智差异」和「架构决策」两块。
